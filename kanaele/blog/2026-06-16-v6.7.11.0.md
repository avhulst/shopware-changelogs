# Shopware 6.7.11.0: MCP-Server, Komponentensystem und stabilere Bestellprozesse

Shopware hat Version 6.7.11.0 veröffentlicht. Das Release bringt mit einem experimentellen MCP-Server und einem komplett neuen Storefront-Komponentensystem zwei strategische Neuerungen mit - plus über 30 dokumentierte Einzeländerungen.

## KI-Anbindung: experimenteller MCP-Server

Shopware integriert erstmals einen MCP-Server (Model Context Protocol). AI-Clients wie Claude Desktop oder Cursor können damit über /api/_mcp direkt mit der Shopware-Instanz arbeiten: Entities verwalten, Konfiguration lesen, Caches steuern, Storefront-Produkte suchen. Alle Operationen respektieren ACL-Berechtigungen; pro Integration lassen sich Allowlists konfigurieren. Aktivierung über das Feature-Flag MCP_SERVER.

## Neues Storefront-Komponentensystem

Auf Basis von Twig UX Components führt Shopware ein Komponentensystem ein, das wiederverwendbare Templates mit SCSS- und JS-Handling erlaubt. Es ist die Grundlage des künftigen Content-Systems, kann aber schon heute in bestehenden Templates genutzt werden. Dazu passend: ein neuer Vite-basierter Dev-Server (composer storefront:dev-server), Theme-Konfiguration als native CSS Custom Properties und Einzeldatei-Referenzen in der theme.json.

## API und Core

Die Sync API erhält sieben neue Foreign-Key-Resolver - Entities lassen sich über ISO-Codes, Locales oder Technical Names statt UUIDs referenzieren. Mail-Templates bekommen Preview- und Send-Routen mit sales-channel-aware Rendering. Im Core werden State-Machine-Übergänge pro Entity gelockt und der Order-Deep-Link-Ablauf konfigurierbar.

## Stabilerer Checkout

Kurzzeitige Elasticsearch- oder OpenSearch-Ausfälle brechen Bestellprozesse nicht mehr ab: Transport-Fehler beim Indexing werden abgefangen, die Bestellung wird regulär abgeschlossen.

## Fazit

6.7.11.0 ist ein Update mit Weitblick: KI-Integration und das neue Frontend-Fundament zeigen, wohin die 6.7er-Linie entwickelt. Für Agenturen lohnt sich eine frühe Evaluierung des Komponentensystems.
